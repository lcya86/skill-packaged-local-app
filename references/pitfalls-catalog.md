# 坑库（现象 → 根因 → 修法 → 通用规则）

每条都来自真实事故。通用规则写在最后一句。

## A. 前端输入与焦点

| 现象 | 根因 | 修法 | 通用规则 |
| --- | --- | --- | --- |
| 输入框打一个字符就脱焦 | `input` 处理器里重写整段列表 `innerHTML`，正在打字的 `<input>` 被销毁 | 渲染拆成「输入区 / 计算区」，打字路径只重算计算区 | **重渲染不许发生在用户正在输入的节点上** |
| 打「20.」把值清了 | `type="number"` 中间态：`value===''` 但 `validity.badInput===true` | 检测到 `badInput` 直接 `return`，不写状态 | 中间态不是用户意图 |
| 金额为 0 时没有编辑入口 | 入口被它要编辑的值门控（`amount===0` 就整行隐藏） | 0/空/null 都要能进编辑态 | **入口不许被自己的值门控** |
| 同屏两个百分比对不上 | 两处各自取分母（一处持仓口径、一处总资产口径） | 分母在 `lib/` 里一次性算好（每行恒定输出加权值），展示层只读不算 | 同屏同分母；口径必须可引用 |
| 「无需调仓」那天页面崩 | 分支出了一条没被主路径覆盖的类型（日期从 Date 变字符串） | 渲染层做防御转换；边界分支单独测 | **边界分支 = 用户第一天/最后一天必走的分支** |
| 过滤后**该有的条目全没了**（一片空白） | 消费聚合结果时用错字段名（写的 `p.id`，库实际返回 `personId`）——判空后把所有人都过滤掉了 | 用正确字段名；**过滤类改动必须在真浏览器里读 DOM 数值断言条数/名字** | 截图看不出「空」是 bug 还是本来就没数据 —— **过滤逻辑只能靠计数验证，不能靠眼睛** |

## B. 数据与写入

| 现象 | 根因 | 修法 | 通用规则 |
| --- | --- | --- | --- |
| 保存报「缺字段」且此后每次保存都报 | 前端某条路径「从零拼 state」漏了键，而服务端是**整份校验**；残 state 留在内存里污染整个会话 | 以 `defaultState()` 起底再覆盖导入内容；写失败自动重拉服务端 state | 整份校验 + 整份写入 ⇒ **前端任何一处拼 state 都要兜底** |
| 测试把真实台账写脏 | 在真页面上做交互测试（页面每次输入都即时落库） | 一切写操作验证走隔离实例；写脏按还原流程 | **真实数据不是测试靶子** |
| 用户看不到自己刚做的改动 | 页面写成功但服务端 rev 没涨（写到内存/被校验拒） | 验收要核**服务端 rev 涨了**，不只看到 toast | 落库判据是数据，不是界面反馈 |
| 空结果覆盖了完整缓存 | 一次失败的上游抓取返回 `{}` 照写 | 报 degraded + 空结果不覆盖非空旧数据 | 缓存不进备份、不可回滚 ⇒ 只允许“更好”的写入 |

## C. 后端与上游

| 现象 | 根因 | 修法 | 通用规则 |
| --- | --- | --- | --- |
| 抓回来是乱码 | 上游返回 GBK，按 UTF-8 解 | 显式 `TextDecoder('gbk')` | 上游编码是契约的一部分 |
| 被判成「这只标的没数据」 | WAF 拦截返回 HTML（HTTP 501），`JSON.parse` 崩了被 catch 成一条 warn | 检测 body 非 JSON 即判 block，与“无数据”分开 | 别把解析失败当业务结论 |
| 页面永久转圈 | 上游挂起（不响应也不断开） | 所有上游 fetch 加超时 | 静默卡死比报错更糟 |
| 早上跑出来的日期差一天 | 日期用 `toISOString()`（UTC） | 一律本地时区函数 | 时区口径写死在一个函数里 |
| 换了数据目录，写进了旧目录 | 进程复用只探活没校验 dataDir | 复用要求 `app` + `dataDir` 都相符 | 复用必须先验身份 |
| 健康端点对外泄露 `dataDir`/rev | 元信息随手写进响应 | 对外前重审所有响应字段 | **对外暴露后，每个字段都是情报** |

## D. 打包与分家

| 现象 | 根因 | 修法 | 通用规则 |
| --- | --- | --- | --- |
| 重装后用户的清单/凭据没了 | 运行时数据躺在 skill 目录 | 挪到数据目录，或登记进补丁清单 | 代码可重装，数据不可 |
| 重装后某个 bug 回来了 | 本地补丁没重放 | 补丁清单 + 重放验收基线 | 补丁不登记 = 隐形回退 |
| Agent 说“装好了”其实没生效 | 技能清单/工具清单是会话启动时的快照 | 按 SKILL.md 绝对路径直接执行流程；重启会话 | 交付判据是**能跑通**，不是“文件在” |
| 同名 skill 在两处，加载报二义性 | skill 存在多份 | 只保留一个规范位置（或走 `skills.external_dirs`） | 一份 skill 一个家 |
| 用户手机上一直跑旧代码，改了不生效 | 静态 JS/CSS 没设 `Cache-Control` → 浏览器按**启发式缓存**不 revalidate（`index.html` 有 no-cache 就以为够了） | 代码/文案类资产一律 `no-cache`（`.html/.js/.mjs/.css/.json/.webmanifest`）；**图片故意保持可缓存**（换图标用换 URL 破缓存） | 「改了不生效」先查缓存头，别急着怀疑代码 |

## E. 协作与门禁（本机环境特有）

| 现象 | 根因 | 修法 | 通用规则 |
| --- | --- | --- | --- |
| 命令卡住直到超时 | 把输出管进解释器（`\| node -e`、`\| python3`）触发审批门禁，用户不在场就空等 | 先落盘（`> /tmp/out.json` 或 `curl -o`）再解析 | 反射动作定成“先落盘” |
| 同样的命令换种写法又被拦 | 门禁判的是 **payload 形状** | 停下来说明“这步需要授权”，别换等价写法硬闯 | 绕过门禁 = 绕过用户同意 |
| 子 agent 报“已修复”，复跑还是坏 | 自报不是证据 | 父 agent 自己复跑（本机侧 + 公网侧各一轮） | 外部副作用要有可验证凭据 |

## F. 复发型坑（第二次出现就别再打补丁了）

| 坑 | 复发记录 | 为什么复发 | 结构性修法 |
| --- | --- | --- | --- |
| 分母/口径不一致 | 4 次（假信号 → 合计≠100 → 现金不在分母 → 同列表两分母） | 每加一个功能就重新取一次分母 | 分母/权重在唯一实现里算好、恒定输出，展示层只读不算 |
| 公网入口无序累积 | 3 次（残留隧道 → 域名失传 → 两条隧道共用日志） | 隧道是长驻外部资源，没人维护清单 | 交付前必列全量进程 + 每条隧道独立日志 + 口令一处罩全部 |
| 前端「从零拼状态」致整页崩 | 2 次（类型当日期用 / 拼 state 丢键） | 有多个入口能重建状态 | 一律 `defaultState()` 起底再覆盖；写失败自动重拉服务端真相 |
| 拿真实数据当测试靶 | 1 次但清规早写过 | 隔离要额外动作，图快 | 把隔离做成默认（模板默认临时目录），真实数据要显式开启 |

**读法**：左列出现第二次时，你的任务不再是“修这个 bug”，而是“让它不可能再发生”。

## G. 后端细节坑（照抄即可避）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 客户端只看到 connection reset，读不到 4xx 的 message | 请求体超限时同步 `req.destroy()` 把还没写出的响应一起掐断 | 超限后继续消费请求体但不再缓存，然后正常回错误码 |
| `Number(null) === 0` 让「显式 null」被当成 0 | 兜底链里只判 `NaN` | 无效输入（`''`/`null`/`undefined`/带千分位串）统一退化为默认值；兜底链里 null 与 undefined 都算「缺失」 |
| 「顺手改共享函数」把别人弄坏 | 被多个调用方共用的函数改动未审 | 改共享函数必须为**所有**调用方补回归用例 |
| 凭据被同机其他用户读到 / 被日志带走 | 明文落盘、权限过宽、错误信息回显 | 原子写 + `chmod 0600` + 独立文件；所有接口只回掩码；报错信息不含凭据 |
| 用户以为“功能没了” | 上游版本的设计取舍（页面故意不带某能力），历史死注释还在源码里 | 先判定“是不是设计如此”再动手；死注释要么删要么标注 |
| 用户看到“看起来正常但已过期”的数字 | 缓存落空后静默回落到旧快照值 | 兜底链每一级都标硬度；数据陈旧就显式标注（停更/过期） |

## H. 外接模型（识别 / 抽取类）

| 现象 | 根因 | 修法 | 通用规则 |
| --- | --- | --- | --- |
| 识别「时好时坏」：这次成功，下次报「无法解析」 | 用的是**推理型**模型：token 预算**先给 thinking**，给少了就 `finish_reason=length`、`content` 为空 | 预算给足（数千级）+ **空内容自动加倍预算重试一次** | 接推理型模型必须实测 `finish_reason` 与 `usage.reasoning_tokens`；「跑通一次」不构成证据 |
| 第一次真用就报「请检查模型名」（502） | 模型名照口述/记忆写（如 `deepseek-v4.1-flash`），上游实际只认 `deepseek-flash` / `deepseek-v4-pro` | 把上游 400 响应正文里的**支持名单**抄下来改配置 | 模型名与参数以**上游自己报的**为唯一真源，别猜 |
| 识别慢、每次费用偏高 | 原图直传（几 MB 截图） | 客户端先缩图：长边 ≤1600px → JPEG 0.82 → 再上传 | 送给模型的不是「证据原件」，是「够用的最小输入」 |
| 批量录入错了就是成倍的错 | 识别与写入耦合在一个接口：模型回什么就写什么 | 拆两段：`识别`（**永不写盘**）+ `提交`（人确认后写）；**服务端强制**，不靠前端自觉 | **批量副作用必须两段式，第二段由人触发** |
| 同一张截图传两次，账翻倍 | 没有「这笔是不是已经记过」的概念 | 同日期 + 同金额 + 同商户判重；命中默认**不勾选**，让人决定 | 幂等键要选**人看得懂的字段**，别用文件哈希 |
| 用户说「它没用我图里的日期」，账里全是今天 | 模型那次生成**漏了日期字段**，服务端**静默**回退成今天（±60 天窗口校验通过所以看不出异常） | 兜底仍可用，但**必须显形**：该条带 `dateFallback`、响应带计数、UI 标「日期未识别 · 记为今天」；同时把日期口径放宽（`M-D` 补年、`10月13日`、带时间、`dateRaw` 二次解析） | **兜底不许静默**——用户看不出被改过，就等于数据在骗人；诊断要能回答「那次到底是模型没给还是服务端丢了」 |
