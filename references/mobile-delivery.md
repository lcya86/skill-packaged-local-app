# 手机交付链路（本机 H5 → 手机桌面）

目标形态：服务跑在**用户自己的电脑上**，手机通过公网 HTTPS 地址访问，加到桌面当 App 用。
一句话规矩：**域名是入口的身份，口令是入口的门锁，图标是入口的快捷方式——三者任一变动都要重新交付。**

## 1. 四段链路总览

| 段 | 解决什么 | 坏了会怎样 |
| --- | --- | --- |
| 本地服务 `127.0.0.1:<port>` | 数据不出本机，只有本机能读真值 | 进程死了/端口换 → 公网地址回 502 或一直转圈 |
| 公网通道 `cloudflared` | 把回环端口映射成一个公网 HTTPS 域名 | 隧道断 → 域名解析正常但连不上；域名换 → 手机图标全废 |
| 身份门禁 `token` | 挡住拿到域名的一切陌生人 | 门禁失效 → 任何人可读写用户数据；门禁过严 → 用户自己进不去 |
| 手机桌面入口（PWA/快捷方式） | 用户不用每次输地址，点图标即开 | 图标指向旧域名/旧口令 → 用户以为「服务挂了」 |

排查顺序永远**自上而下**：本机能开（§2）→ 公网可达（`verification-recipes.md` §3 五连）→ 门禁放行（§4）→ 手机侧（§5）。跳过前两段直接折腾手机 = 白费。

## 2. 本地服务落点

- **默认只监听 `127.0.0.1`**。不设 `0.0.0.0` 就不存在同网段被扫的风险；要给局域网用，走第 4 节档①。
- 启动脚本从 `<data_dir>/token.env`（权限 `0600`）读入环境变量再 exec 服务进程：
  **口令不许进 argv**，`ps aux | grep <app>` 里不能出现口令明文。
  - 反例：`node server.mjs --token=<token>` —— 同机任何用户 `ps` 一次就拿到。
  - 正例：`set -a; . <data_dir>/token.env; set +a; exec node server.mjs`。
- 落点写进 `<data_dir>/runtime.json`：`{ port, pid, startedAt, dataDir }`。复用前校验 `dataDir` 与 `app` 字段，
  否则换数据目录后会连到旧目录的实例。
- 启动后**轮询健康端点**确认就绪，不要 `sleep 5` 赌时间：

```bash
for i in $(seq 1 50); do curl -sf "127.0.0.1:<port>/api/health" && break; sleep 0.2; done
```

- 长跑注意：`caffeinate -i` **只挡空闲睡眠，合盖仍断**；断电/重启后端口与进程都要重新确认
  （`runtime.json` 里的 pid 可能已不存在）。

## 3. 公网通道（quick tunnel vs named tunnel）

quick tunnel 的四个事实：

| # | 事实 | 后果 |
| --- | --- | --- |
| ① | 每次启动是**随机域名** | 交付链接不可复用 |
| ② | 进程或宿主重启即换域名 | 手机图标第二天就失效 |
| ③ | **无 uptime 保证** | 不能当唯一入口做无人值守 |
| ④ | **新隧道不会踢掉旧隧道** | 等于多开一个被遗忘的公网入口 |

- **关键后果：域名一变，所有手机桌面图标全部失效**——图标里存的是域名。因此**每次换域名都必须重新交付卡片**
  （第 6 节），并在卡片里写明「地址可能变，失效就重新加一次」。
- 要长期稳定就上 **named tunnel**：固定域名，代价是需要 Cloudflare 账号 + 一个自有域名（并做 DNS 绑定）。
  自用看板类默认 quick tunnel 够用；「用户开始抱怨每天要重加图标」就是升级信号。
- 卫生（交付前必做）：
  - **每条隧道独立日志文件**：共用同一日志时，后启动的 `> 重定向` 会截断前一条写下的域名行 → 域名失传。
  - 列出**全部**隧道进程与年龄，再决定停哪条；停历史遗留进程**先要批准**：

```bash
pgrep -fl cloudflared
ps -o pid,lstart,command -p $(pgrep -f cloudflared | tr '\n' ',' | sed 's/,$//')
```

- 设计要点（代理头判定、回环豁免、401 分形态等）见 `maintenance-playbook.md` §3；本节只讲交付视角：**一次只交付一条隧道、一个域名、一张卡片。**

## 4. 身份门禁三档

| 档 | 适用场景 | 强度 | 实现要点 | 不适用 |
| --- | --- | --- | --- | --- |
| ① 无鉴权（仅局域网） | 同 WiFi、明确告知同网段谁都能读写 | 无 | 绑 `0.0.0.0` + 给局域网地址 | 任何走公网隧道的情况 |
| ② **共享口令 token（默认档）** | 单人自用、走公网 | 中（持有即有权） | 见下 | 多人共用一份数据需分人审计 |
| ③ Cloudflare Access | 多用户共享同一份数据、要按人区分与审计 | 高（认人） | 邮箱 OTP / 身份提供商在前置校验 | 单人自用属过度设计 |

### 档② 共享口令 token（默认交付形态）

- 首次 `/?token=<口令>` → 校验通过后 `Set-Cookie: …; HttpOnly; SameSite=Lax; Path=/; Max-Age=<n>` + **302 到去掉口令的 URL**（URL 里不留口令）。
- **纯回环且无代理头则豁免**：CLI 探活、进程复用、本机浏览器零改动。
- 判定「外部」靠**代理头**（`cf-connecting-ip` / `x-forwarded-for`）而非 `remoteAddress`——隧道进程从本机回连，只看 `remoteAddress` 会把整条隧道当「本机」放行。
- 口令比较用**恒定时间比较**（`crypto.timingSafeEqual`），别用 `===`。
- 401 分形态：`/api/*` 回 JSON、页面回极简 HTML，**两者都不回显路径与业务数据**。
- **未设口令变量时行为与旧版逐字段一致**（这是「默认不变」的验收基线，对撞比法见 `verification-recipes.md` §4）。
- **401 页必须带一个口令输入框**：口令轮换或 cookie 过期后，用户直接在页面上重新输入即可，
  **不用重加桌面图标**。这是「用户以为坏了」的第一大来源的解药。

### 口令轮换与撤销

- 怎么换：生成新口令写回 `0600` 文件 → 重启服务（口令在启动时读入环境变量）。
- 换完谁要重新授权：**所有持有旧 cookie 的设备**（含用户手机、任何浏览器）。
  cookie 失效后落到 401 页，输入新口令即可；**桌面图标不用动**（图标存的是域名不带口令）。
- 泄露处置：立刻轮换 + 换域名（旧域名随旧隧道一起停），两件事都做才算撤销。

## 5. 装进手机桌面

### 前置资产

- `manifest.webmanifest`：`name` / `short_name` / `display: standalone` / `start_url` / `theme_color` / `icons`（192 + 512）。
- `apple-touch-icon`：**180×180** PNG；页面 `<head>` 加 `apple-mobile-web-app-capable` 与 `apple-mobile-web-app-title`。
- **图标 PNG 在本地生成**：先在**一张大母版**上渲一次，再降采样出各尺寸 —— **不要**按每种尺寸分别用无头浏览器截 SVG：

```bash
# ① 母版：SVG 只给 viewBox，width/height 用 100%（写死尺寸会被裁，见下）
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --no-sandbox \
  --hide-scrollbars --window-size=1024,1024 --virtual-time-budget=3000 \
  --screenshot="/tmp/icon-master.png" "file://$PWD/icon.svg"
# ② 降采样：写成一个脚本落盘再跑（不要把代码喂给解释器）
#    tools/make-icons.py: 母版 LANCZOS resize 到 512 / 192 / 180 并各存一份
python3 tools/make-icons.py
```

**别按尺寸分别截 SVG**：SVG 若写死 `width="512" height="512"`，用 `--window-size=180,180` 截它时，浏览器**不缩放、直接裁左上角** —— 你会拿到一张"碎片"而不是缩小的图标。曾真实交付过一版：512 那张正常、192/180 那两张是左上角碎片；iPhone 把碎片**放大铺满**图标位，用户看到的是「一个巨大的色块」。改成 ① 母版 + ② 降采样后，三张的字形占比才可能一致（实测 65.0/65.1/65.0）。

本机没有 Chrome 也可以：`rsvg-convert`／`qlmanage`／设计软件导出都行，要求只是拿到 **180 / 192 / 512 三张 PNG**（headless 参数随版本而异，以实际可用为准）。

### 图标交付前必查（用像素量，别只用眼睛看）

| 检查 | 判据 | 怎么量 |
| --- | --- | --- |
| 底色**满幅** | 四角像素 = 底色，**α=255**（不能透明） | 读 PNG：四角 RGBA；有透明角说明图标自带了圆角 —— 圆角应交给系统遮罩 |
| 三张**同源** | 字形占宽比例三张一致（±1%） | 白色像素 bbox / 画布宽 |
| **居中** | 上下留白差、左右留白差 ≤ 2%（母版尺度） | 同上 |
| 尺寸 | 180×180 / 192×192 / 512×512 | `sips -g pixelWidth -g pixelHeight` |

`--default-background-color=00000000`（透明底）用在**满幅方形**图标上是反效果：它会把"没有背景色"的假设带进结果。满幅图标直接用默认白底再被底色矩形盖住即可。

### 换了图标必须换 URL（否则平台死缓存）

iOS 与 Chrome 会**长期缓存** `apple-touch-icon` 与 manifest 里的图标，光改文件内容不生效。可靠做法是**加版本后缀**再指向它：

- 文件名：`apple-touch-icon-v2.png` / `icon-192-v2.png` / `icon-512-v2.png`（旧的同名文件保留一份，覆盖为新内容，兼容"约定路径"回退）
- 三处引用一起改：`<link rel="apple-touch-icon">`、`<link rel="icon">`、manifest 的 `icons[].src`（manifest 可再带 `?v=2`）
- 同时告知用户：**先长按删掉桌面旧图标再重加** —— 不删旧的，桌面留着的还是旧图标

### start_url 的坑（重点）

- **不要把带口令的 URL 当 `start_url`**：口令会留在 URL、浏览历史与截图里，等于把门锁挂在门上。
- 正确做法：**首次带口令授权一次 → 之后图标打开无参 URL，靠 cookie 直接进**。
  `start_url` 写无参的根路径（`/`）。
- cookie 失效时：图标打开落到 401 页 → 页面上的输入框重新输入口令 → 照常进。

### 三套「添加到桌面」步骤

每条只给「点哪里 → 看到什么」，失败时的排查另附。

**iOS（必须用 Safari）**

- 点哪里：Safari 打开地址 → 底部「分享」 → 「添加到主屏幕」 → 可改名称 → 「添加」。
- 看到什么：主屏幕出现带自定义图标的入口；点开是**无地址栏**的独立窗口。
- 失败排查：Chrome for iOS **不支持添加到主屏幕** → 换 Safari；图标是白块 → `curl -I` 探 `apple-touch-icon` 是否 200、是否 180×180。

**安卓（Chrome）**

- 点哪里：Chrome 右上角 `⋮` → 「添加到主屏幕」（部分版本显示「安装应用」）→ 确认。
- 看到什么：有 manifest 且满足条件时是**独立窗口**；否则只是浏览器快捷方式（点开仍带地址栏）。
- 失败排查：只是快捷方式 → 检查 manifest 是否被正确引用（`<link rel="manifest">`）、图标 192/512 是否可达、是否 HTTPS。

**鸿蒙（HarmonyOS）**

- 点哪里：**华为浏览器** 打开地址 → 菜单 → 「添加到桌面」。
- 看到什么：桌面出现快捷方式入口。
- 失败排查：换华为浏览器；菜单项措辞**以实际菜单为准**（不同版本可能不同）。
- **不要承诺**元服务 / 原生打包——本链路交付的是网页入口，不是原生 App。

### 三系统共同注意

- **HTTPS 是前提**（隧道已提供）；HTTP 下 PWA 安装能力被浏览器禁用。
- standalone 下「回到桌面再进」可能**冷启动重载**而非恢复现场，属 WebApp 固有行为，用户问起如实说明。

## 6. 交付卡片模板（可直接复制给用户）

```
你的看板已经可以用了，照下面三步加到手机桌面。

1) 地址：https://<随机域名>.trycloudflare.com
2) 口令：<token>
3) 首次授权（只做一次，浏览器里打开）：
   https://<随机域名>.trycloudflare.com/?token=<token>
   看到页面正常打开、地址栏里的口令自动消失，就是成功了。

加到桌面：
- iPhone：用 Safari 打开上面地址 → 分享 → 添加到主屏幕 → 改个名 → 添加
- 安卓：Chrome 右上角 ⋮ → 添加到主屏幕
- 鸿蒙：华为浏览器 → 菜单 → 添加到桌面
加完之后点图标就进，不用再输地址和口令。

打不开时的三步自查：
- 第 1 步：电脑上服务是不是还开着（关电脑 / 关终端就停了）
- 第 2 步：地址栏里的域名对不对（地址可能变，变了要重新加一次图标）
- 第 3 步：页面如果出现口令输入框，把口令再输一遍

隐私提醒：
- 别把链接转发给别人（拿到链接 + 口令 = 能读写你的数据）
- 别截图带口令的那条 URL 发出去
```

## 7. 二维码

- 手机输长 URL 很痛苦 → 交付时生成二维码更省事。
- **必须在本地生成，绝不用在线二维码网站**——那等于把**带口令的 URL 送给第三方**。
- 本地生成的命令形状（示例，按实际可用工具选一种）：

```bash
# 用本机已有工具，别走网络
qrencode -o /tmp/<app>-qr.png "https://<随机域名>.trycloudflare.com/?token=<token>"
# 或 python: qrcode.make(url).save("/tmp/<app>-qr.png")
```

- 二维码放**首次授权链接**（带口令），与卡片说明保持一致；截屏时别让链接文本与二维码同时入镜（泄漏路径同 §8）。

## 8. 坑（现象 → 根因 → 修法）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 交付后有陌生人能读数据 | 同时开着多条隧道，只记了一条，另一条无门禁入口被遗忘 | 交付前 `pgrep -fl cloudflared` 列全量、逐条确认门禁一致；停遗留进程前先批准 |
| 第二天不知道域名是什么 | 多条隧道共用同一个日志文件，后启动的 `>` 截断前一条的域名行 | **每条隧道独立日志文件**；域名落盘一份 |
| 公网能拿到数据目录、端口等元信息 | 健康端点回 `dataDir` 等内部元信息 | 健康端点只回 `{ok:true}`，元信息仅本机回环可见 |
| 同机其他用户拿到了口令 | 口令进了 argv，`ps` 里可见 | 口令走 `0600` 文件 → 环境变量，**不进 argv** |
| 口令随截图/转发泄漏 | 口令写在 URL 里被截图或转发；`start_url` 带了口令 | 授权后 302 去掉 URL 口令；`start_url` 用无参根路径；卡片里写明别转发别截图 |
| 手机图标点了白屏 / 报错 | 域名换了，图标还指向旧域名 | 域名一变就重新交付卡片；卡片注明「地址可能变」 |
| 用户说「服务挂了」，其实是 cookie 过期 | 401 页没给输入框，用户以为进不去 = 挂了 | **401 页必须带口令输入框**；卡片写「出现输入框就再输一遍口令」 |
| 图标是个模糊白块 | `apple-touch-icon` 缺失或尺寸不对 | 本地渲染 180×180 PNG 并 `curl -I` 确认可达 |
| 图标显示为**巨大色块 / 只有一角** | 按各尺寸分别截 SVG → SVG 写死了 width/height → 浏览器裁左上角，拿到"碎片"；手机把碎片放大铺满 | 改成"1024 母版 + LANCZOS 降采样"；并用像素 bbox 量三张占比是否一致 |
| 图标比别的 App **小、被塞进白块** | 图标自带了圆角/透明角，不是满幅 | 改成满幅方形底（α=255），圆角交给系统遮罩 |
| 换了图标但手机**还是旧的** | iOS/Chrome 死缓存图标 | 图标 URL 加版本后缀（`-v2`）并同步 manifest；让用户先删旧图标再重加 |
| 合盖第二天公网不通 | 以为 `caffeinate -i` 挡住了所有睡眠 | 明确告知「合盖仍断」；重启后重查端口与进程 |

## 存疑项

- 鸿蒙华为浏览器「添加到桌面」菜单项的确切措辞随版本变化，**以实际菜单为准**，不要照抄本文字面。
- 部分安卓机型「添加到主屏幕」与「安装应用」文案并存，取决于 Chrome 版本与 manifest 完整度，**以实际弹出项为准**。
- iOS「分享 → 添加到主屏幕」在不同 iOS 大版本上的入口图标位置可能略有差异，**以实际界面为准**。
