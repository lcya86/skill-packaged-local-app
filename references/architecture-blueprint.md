# 架构蓝图与模板

来源：一个自用的看板类项目（Node 18+ / 零依赖 / 无构建）。可迁移到其它栈，分层的**职责边界**不变。

## 1. 目录骨架（可直接照抄）

```text
<skill_dir>/
├── SKILL.md                     # 触发条件 / 操作流程 / 口径声明 / 排障
├── README.md                    # 给人看的：它是什么、怎么装、边界在哪
├── INSTALL.zh-CN.md             # 分宿主的安装说明（含“别装到默认 profile”这类坑）
├── docs/
│   ├── DESIGN-<功能>.md         # 每个功能一份：期望值表 + 契约 + ⛔不做清单
│   └── INTEGRATION-TEST-<功能>.md
├── INTEGRATION-TEST-REPORT.md   # 首版整体的联调报告（模块契约实测）
├── scripts/
│   ├── cli.mjs                  # Agent 入口（子命令 + JSON 输出）
│   ├── server.mjs               # 本机服务（静态 + API + 上游代理）
│   ├── store.mjs                # 数据层（原子写/备份/rev/校验/migrate）
│   ├── lib/<domain>.js          # 领域纯逻辑（页面与 CLI 共用·只此一份）
│   └── test/*.test.mjs          # 零依赖断言；含 spec.test.mjs（校验本 skill 的 SKILL.md）
└── ui/                          # 无构建前端
    ├── index.html               # 脚本加载顺序即契约，id 即契约
    ├── app.css
    └── app.js                   # 串行写队列 + rev 乐观锁 + CONFLICT 重取
```

## 2. 数据契约模板（F0 的产物）

写 `docs/DESIGN-<功能>.md` 时逐项回答：

| 问题 | 为什么要写死 |
| --- | --- |
| 字段名 & 类型 | 页面/CLI/备份还原都按它对齐 |
| 谁写 / 谁读 | 出现第三处写入方 = 口径要分叉 |
| 缺键怎么办 | 老数据不许因缺新键而整份校验失败（**视为默认值**，不列为必填） |
| 0 / null / 空串的语义 | 「0」常是合法值（目标 0%）≠「没设置」 |
| 迁移策略 | 加字段走 migrate，不改写老文件的语义 |
| **人手算的期望值表** | 验收时照着对，比“看起来对”可靠 |

三条硬约束（写进设计文档，改代码时照守）：

1. **默认零变化**：新开关关掉时，输出与旧版逐字段一致。
2. **老数据不许 400**：新键一律软校验。
3. **不许动既有键的类型/含义**：新语义走新字段（例：只接受 6 位代码的表里，塞不进别的对象）。

## 3. API 契约模板（F4 前后写）

```text
GET  /api/health          → { ok, app, initialized, rev, ... }   # ⚠ 对外前审字段，别回本地路径
GET  /api/state           → { ok, state, rev }
PUT  /api/state           ← { state, baseRev } → 200{rev} | 409{rev,state} | 400{message}
  409 → 调用方必须「重取最新 → 重放本次修改」，不许直接覆盖
GET  /vendor/<lib>.js     → 直接端出 scripts/lib/<domain>.js（no-cache）⇒ 页面与 CLI 同源
POST /api/<动作>           ← 有副作用的动作单列端点；纯解析类不许写盘
```

规则：

- **读接口零副作用**，「纯解析/预览」与「落库」必须是两个端点。
- **写接口一律带 baseRev**；409 是正常路径，不是错误。
- 上游抓取加**超时**（挂起不响应的上游会让前端永久转圈，静默卡死比报错更糟）。
- CORS：能浏览器直连的上游（有 `access-control-allow-origin`）就直连，本机代理做**回落**；别一切都过代理。

## 4. 分阶段验收基线（记数字，后续只多不少）

```bash
node --test scripts/test/*.test.mjs     # 首版 129 断言 → 加功能后 277，全程不回归
node scripts/test/spec.test.mjs         # SKILL.md frontmatter 合规（防宿主静默丢弃）
```

- 记录**每套的断言数与文件清单**，写进 SKILL.md；改动后比对新旧数字。
- spec 类测试值得单列：frontmatter 不合规的 skill 在多数宿主上**不报错、只是不触发**，极难排查。

## 5. 何时该拆新 skill

出现下列任一情况，把这份 skill 拆成「应用本体」+「操作层补充」（实测有效的拆法：`<app>` 本体 + `<app>-ops` 操作层）：

- 领域口径/业务规则开始占 SKILL.md 一半以上（应用本体要能给别人用，口径是本机特有的）；
- 上游包由别人维护（你只写补充与补丁清单）；
- 操作流程长到需要 5+ 个 references。

拆法：**应用本体 = 架构与接口**；**操作层 = 口径、坑、还原流程、与用户的约定**。两文互相引用，不重复。
