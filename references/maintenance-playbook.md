# 维护手册（长期跑的东西）

## 1. 本地补丁清单（第三方包场景的命门）

第三方包 = 重装即丢。每处本地改动登记三件事：**改了哪些文件 / 为什么 / 重放后怎么验收**。

| # | 补丁 | 文件组 | 默认行为 | 重放后验收 |
| --- | --- | --- | --- | --- |
| ① | 数据文件 | `scripts/<runtime>.json` | — | 文件存在 + 内容含用户的清单 |
| ② | 监听开关 | `scripts/server.mjs` | 不变（默认仍 127.0.0.1） | 不设变量时行为逐字段一致 |
| ③ | 逻辑修正 | `scripts/lib/*.js` | 不变 | 原测试断言数不回归 |
| ④ | 新功能（一组文件） | 新增 `scripts/lib/*`、`scripts/*.mjs`、`ui/*`、`scripts/test/*` | 关闭时零变化 | 新测试全过 + 老测试不回归 |
| ⑤ | 页面体验 | `ui/index.html`、`app.css`、`app.js` | 不可回退 | 真机点一次（见 verification-recipes） |
| ⑥ | 访问口令 | `scripts/server.mjs` + 数据目录里的 `token.env`/启动脚本 | 未设变量 = 旧行为 | 公网五连 |

规矩：

- **两份副本必须同步**：安装副本（profile skills 目录）+ 源码副本，改完 `shasum -a 256` 比对；
  全树 `diff -r` 只允许剩“运行时数据文件”（那本来就不该进源码仓）。
- **补丁清单写进 SKILL.md**（不是写在会话里）——下个 Agent 只有 SKILL.md。
- **升级上游时的顺序**：先读新版 diff → 判断补丁是否已被上游吸收 → 重放未吸收的 → 跑验收基线 → 再交付。

## 2. 进程与端口

- 长驻服务两种状态：**没跑**（启动）/ **在跑**（复用）。复用前必须校验身份（`app` 字段 + `dataDir` 相同），
  否则换数据目录后请求会被路由到旧目录的实例。
- 端口从固定基准起**探测空闲**（8765/8080 这类太容易撞）。
- 启动后**轮询健康端点**确认，而不是 sleep 固定秒数。
- CLI 里拉起的服务必须**脱离父进程**（否则父命令一结束服务就死）；交互式场景下也要防它挂住终端。
- 改 `scripts/*` → **必须重启**；改 `ui/` → **只需刷新**。交付前 `curl <新路径>` 验证新代码真在跑（404 = 旧进程）。
- 收尾别留孤儿：测试实例、临时隧道、后台进程都要清，清理后确认端口释放。

## 3. 隧道与远程访问

- 先分流：**同 WiFi 够不够**？够就绑 `0.0.0.0` + 给局域网地址（无鉴权服务 = 同网段谁都能读写）。
  不在同一网络才上隧道。
- quick tunnel 的四个事实：① 随机域名，进程/宿主重启即换；② 无 uptime 保证；③ `caffeinate -i` 只挡
  空闲睡眠（合盖仍断）；④ **新隧道不会踢掉旧隧道**。
- **多重隧道 = 多个被遗忘的公网入口**。交付前 `pgrep -fl <tunnel>` 列全量、`ps -o pid,lstart` 报年龄；
  停历史遗留进程**先要批准**。
- **日志路径必须每条隧道独立**：共用同一个日志文件时，后启动的 `>` 重定向会截断前一条的域名行 → 域名失传。
- **口令加在服务端**，一处罩住所有指向该端口的隧道；别逐条改隧道。
- 门禁设计（可直接照搬）：
  - `<APP>_TOKEN` 未设 = 旧行为（无鉴权）；设了才启用。
  - 判定“外部”靠**代理头**（`cf-connecting-ip` / `x-forwarded-for`）——隧道进程从本机回连，
    只看 `remoteAddress` 会把整条隧道当“本机”放行。
  - 纯回环且无代理头 → 豁免（CLI 探活、进程复用、本机浏览器零改动）。
  - 首次 `/?token=…` → `Set-Cookie: …; HttpOnly; SameSite=Lax; Path=/; Max-Age=<n>` + 302 去掉 URL 里的口令。
  - 401 分形态：`/api/*` 回 JSON，页面回极简 HTML；**都不回显 URL/路径/业务数据**。
  - 口令比较用恒定时间比较（`crypto.timingSafeEqual`）。
  - 口令存数据目录的 `0600` 文件，由启动脚本读进环境变量（**不进 argv**，`ps` 里看不到）。

## 4. 数据血统

- **唯一真相**在数据目录的 `state.json`；`backups/` 每次写入一帧，可**逐帧复盘用户操作序列**
  （比只看 rev 有用：能排出“先录现金 → 再开开关 → 再点生成目标”的完整动作链）。
- 备份目录要设上限（如保留最近 20 份），否则无限增长。
- 用户的“手改到一半”的值会被逐格即时落库（62.2 → 62 → 6）→ 看到这类值**先问一句**，
  别当意图去推结论；同时提醒他“这格已被覆盖”。
- 备份不在异地时，明确告诉用户“换机/清目录就没了”。

## 5. 分发边界（给别人的东西）

- **安装脚本不许自动改用户 config**：要改配置就提供 `--print-config` 打印片段让用户自己贴——实测这是被接受的做法，
  自动改配置的脚本不该跑。
- **凭据不进 argv**：启动脚本从 `0600` 文件 source 进环境变量；`ps` 里不能看到口令。
- **演示数据与真实数据必须可辨**：`--mock`/`--demo` 的数据带明显水印或时间戳，否则会被当成真实读数。
- **交付三件套**：README（是什么/怎么装/边界）+ INSTALL（分宿主，含“别装到默认 profile”这类坑）
  + 集成测试报告（模块契约与真缺陷的复现/修复/复验）。少一件，下一个人就要重新踩一遍。
- **维护一张复发清单**（哪类坑、第几次）放在 SKILL.md 里——复发次数是架构债的度量。
- **重装后的第一件事**：不是“打开看看”，而是按补丁清单重放 + 跑验收基线（断言数、默认不变对撞）。
